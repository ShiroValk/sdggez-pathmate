# Feature Specification: 移除妙搭平台依赖并补齐独立运行能力

**Feature Branch**: `main`（无分支创建钩子，规格目录独立于分支）

**Created**: 2026-10-04

**Status**: Implemented with documented limitations（截至 2026-10-09，T001–T076 已完成，包含 converge 后 T068–T076 的补充实施及适用补验；最终记录为 9 套件 22 项集成测试及 lint 通过。历史高德 Key 处置按用户决定暂缓，部分浏览器定位仍有环境限制，不声明完整规格全部达标；当前证据以 [verification.md 最终补验](verification.md#2026-10-09-最终补验) 为准）

**Governing Constitution**: [PathMate Constitution v1.0.1](../../.specify/memory/constitution.md)

**Input**: User description: "PathMate 在没有妙搭账号、平台 SDK、平台网关及平台数据库的环境中安装、构建、启动和运行已有业务；先检查迁移并复用验证合格成果，补齐认证、授权、验证、持久化、请求、错误、日志和配置，保持兼容，提供迁移回滚、本地说明和可复现验收；保留 001 的评估范围，不扩展为全部 PRD。"

## Clarifications

### Session 2026-10-04

- Q: 本次独立运行必须在哪些环境中完成验收？ → A: Windows 本机运行，浏览器本机访问；不包含局域网手机访问或公网部署。
- Q: Windows 本机的数据库安装与运行，本次需要支持哪种方式？ → A: 采用 Docker Desktop 运行本地 PostgreSQL，应用仍在 Windows 本机运行；运行说明须面向初次开发者解释并覆盖 WSL 2、虚拟化及 Docker 的准备步骤，不要求原生 PostgreSQL 安装路径验收。
- Q: 本次是否需要保留并迁移已经存在的业务数据？ → A: 从空库开始，不迁入现有业务数据；仍须用测试数据验证后续数据库升级和回滚，不以真实旧数据或平台身份映射作为完成条件。
- Q: 本次真实运行中，家属账号与长者账号应如何访问同一位长者的资料？ → A: 家属与长者使用独立真实账号，经明确授权建立一对一照护关联；家属管理其照护资料，长者仅访问本人允许的数据和操作，不凭姓名、手机号或客户端提交的长者编号自行建立关联。
- Q: 本次保留的演示体验，应如何处理认证和数据保存？ → A: 保留显式前端演示和演示账号；前者不写业务数据库，后者使用真实本地认证并保存隔离的演示数据。验证码、模拟定位、叫车、求助、告警及通知仍为演示，保存记录不代表真实服务已执行。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在没有平台环境的机器上运行应用 (Priority: P1)

作为接手者，我希望仅凭项目和运行说明完成全新安装、构建与启动，访问已有页面和本地业务服务，无须妙搭账号或平台环境。

**Why this priority**: 独立运行是使用全部已有业务的前提。

**Independent Test**: 在无平台账号、凭证、软件和配置的干净 Windows 环境，按说明完成安装、构建、空数据库初始化、启动及本机浏览器页面访问。

**Acceptance Scenarios**:

1. **Given** 干净环境与文档列明的普通运行前提，**When** 按步骤安装、构建、初始化并启动，**Then** 全部步骤成功，首页与现有业务入口可访问，请求不依赖平台网关或平台数据库。
2. **Given** 未配置地图，**When** 打开地图界面，**Then** 明确显示地图不可用及配置提示，注册、登录、资料管理、设置和非地图流程仍能运行。
3. **Given** 必填配置缺失或无效、数据库不可连接或结构未准备好，**When** 启动，**Then** 明确失败并指出可操作的原因，不宣称业务就绪、不用演示数据掩盖故障、不泄露凭证。
4. **Given** 构建后的应用，**When** 按正式启动说明访问或刷新现有业务入口，**Then** 页面及业务请求正常，不依赖开发服务才可使用。

---

### User Story 2 - 使用真实本地账号并可靠退出 (Priority: P1)

作为用户，我希望注册和登录后使用自己的资料，退出后旧会话不能访问受保护内容，账号错误或故障时能知道实际失败原因。

**Why this priority**: 展示登录成功不能替代身份验证，退出必须撤销服务端访问资格。

**Independent Test**: 注册 A，退出并用正确密码登录、验证当前身份；使用错误密码、伪造凭证、失效凭证及退出前凭证访问受保护内容。

**Acceptance Scenarios**:

1. **Given** 未注册的有效账号与完整资料，**When** 注册、退出并重新登录，**Then** 账号和资料真实保存，会话关联正确账号；重复注册被拒绝，不留下半完成账号或资料。
2. **Given** 空输入、错误密码或服务不可用，**When** 普通登录，**Then** 明确失败，不创建有效会话、不自动进入演示、不显示登录成功。
3. **Given** 有效会话，**When** 查询当前身份或刷新页面，**Then** 服务端确认身份和角色，页面不凭本地角色选择器获得权限。
4. **Given** 已登录用户，**When** 成功退出后使用旧凭证，**Then** 所有受保护操作均被拒绝，浏览器清除该用户会话与受保护缓存。
5. **Given** 退出时服务不可用，**When** 尝试退出，**Then** 清除本地敏感状态，明确提示服务端撤销未确认及后续处理方式，不声称服务端退出成功。
6. **Given** 会话达到公布的有效期或被撤销，**When** 再次使用，**Then** 必须重新登录，不能继续读写资料。

---

### User Story 3 - 保证隔离、角色权限和数据真实性 (Priority: P1)

作为家属或长者，我希望只访问获授权资料，保存结果跨页面和重启保留，无效输入不能损坏数据。

**Why this priority**: 去除平台后仍须承担身份、归属与权限责任，避免跨家庭泄露和数据丢失。

**Independent Test**: 两个未关联的家属账号创建不同资料，另用一个长者账号经明确授权关联其中一位长者，分别验证授权访问、未关联拒绝及角色越权；保存后重启应用和数据库，核对结果。

**Acceptance Scenarios**:

1. **Given** 无照护授权关系的家属账号 A、B，**When** B 枚举、查询或直接提交 A 的长者及关联资源标识，**Then** 不返回 A 私有资料、不允许修改或删除；聚合界面和设置同样隔离。
2. **Given** 长者角色凭证，**When** 执行家属管理或伪造角色、归属字段，**Then** 服务端按权限矩阵拒绝越权，修改页面状态不能扩大权限。
3. **Given** 有效输入，**When** 保存长者、联系人、行程、设置、围栏或地点并刷新、重登、重启应用及数据库，**Then** 读回相同字段含义及关联，包括地点地址与坐标。
4. **Given** 类型、格式、长度、范围、枚举、嵌套字段或字段关系无效，**When** 绕过前端直接提交，**Then** 在可信边界拒绝，不写数据、不产生半完成结果，提供明确反馈。
5. **Given** 重复提交、并发注册或关联保存中途失败，**When** 处理完成，**Then** 不产生重复唯一账号、孤立归属或不一致记录；重复迁移不破坏已有数据。
6. **Given** 独立长者账号尚未关联，**When** 请求照护资料或仅提交姓名、手机号、长者编号尝试关联，**Then** 拒绝访问及未经授权的关联；经明确授权建立一对一关联后，允许读取本人所需资料，但拒绝其他长者及家属管理操作。
7. **Given** 已建立的照护关联，**When** 授权被撤销或相关长者被删除，**Then** 长者账号不能再通过旧会话或缓存访问该照护资料；并发关联不得使同一长者或长者账号具有多条有效关联。

### User Story 4 - 理解演示边界并保留已有流程 (Priority: P2)

作为用户和维护者，我希望迁移保留受支持页面和接口含义，明确区分演示与实际认证、保存结果。

**Why this priority**: 不能破坏调用约定，也不能使模拟能力看起来成为真实照护服务。

**Independent Test**: 用迁移前合法调用样例及页面流程复核新环境，分别检查普通业务与显式演示入口。

**Acceptance Scenarios**:

1. **Given** 已登记的受支持契约及合法样例，**When** 在独立环境执行，**Then** 调用方式、结构、字段含义、错误约定和可观察结果兼容；安全修复影响单列说明并回归验证。
2. **Given** 显式选择前端演示或演示账号，**When** 使用演示密码、验证码或模拟定位、叫车、求助、告警、通知，**Then** 入口与结果说明演示类型及保存边界，不宣称真实短信送达、手机号核验、叫车或通知完成；演示账号的本地密码认证及数据保存本身是真实操作。
3. **Given** 平台专属组件，**When** 替换或清理，**Then** 有实际引用及使用证据；使用中的能力有替代验收，确认未使用的才可清理。
4. **Given** 显式前端演示，**When** 修改资料或使用模拟操作，**Then** 不写业务数据库，界面明确提示演示变化不代表服务端保存；切换到普通账号不带入演示资料、会话或授权。
5. **Given** 演示账号及独立普通账号，**When** 登录、保存并重启，**Then** 演示账号仍执行真实密码、会话、权限、输入验证和持久化检查，演示资料可恢复且与普通资料隔离；普通账号不能访问未授权演示资料，演示账号不能访问普通资料。

---

### User Story 5 - 可交接、可诊断、可恢复 (Priority: P2)

作为维护者，我希望依据依赖对照、文档和验收证据接手，迁移失败时恢复数据及兼容运行状态。

**Why this priority**: 能启动不足以支持维护，迁移必须有可执行的恢复路径。

**Independent Test**: 接手者复现验收，在隔离的本地测试数据库执行初始化、版本升级和回滚，并据脱敏日志定位认证失败及保存失败。

**Acceptance Scenarios**:

1. **Given** 当前代码及迁移证据，**When** 审阅交付，**Then** 原依赖逐项对应实际用途、替代能力、处置与验收，已验证成果可复用，未验证成果不冒充通过。
2. **Given** 从空库建立的本地测试数据及升级前备份，**When** 执行版本升级、核对后回滚，**Then** 账号归属、关联及字段含义一致，恢复后应用兼容；初始化、重复执行及升级失败的恢复均有结果。
3. **Given** 认证、越权、输入或保存失败，**When** 查看反馈和日志，**Then** 可关联到操作及原因，不暴露密码、完整会话凭证、地图 Key 或多余个人资料。

### Edge Cases

- 无数据库配置与仅缺地图配置区别处理；地图 Key 无效、加载失败或定位被拒绝须明确不可用。
- 新库缺表或残留平台自定义字段类型，不能以连接成功认定业务可用。
- 空归属、孤立关联和演示数据不能通过共用空标识授权；本次不导入平台旧身份或旧业务数据，初始化不得清空或覆盖意外发现的非空数据库。
- 上个账号的缓存、过期凭证或页面所选角色与已验证角色不同，依据服务端身份重载。
- 账号预检查失败不等于账号可用；并发注册及初始化部分失败不能返回成功。
- 非法标识、未知字段、超长字符串、不完整嵌套对象、非法日期时间和经纬度、字段关系冲突须拒绝。
- 断网或保存失败保留可重试输入，不把暂存、默认值当作保存完成。
- 退出请求未送达时，本地清理与服务端撤销分别表达。
- 演示账号认证或数据库不可用时，明确失败，不自动转为前端演示；显式选择前端演示仍不写业务数据库。模式切换清除上一个模式的会话及资料缓存，演示凭证不产生普通资料权限。
- 老契约允许的可选空值与无效输入分开登记，不能以验证静默改变合法语义。
- 不可逆转换须从验证过的备份恢复，说明迁移后新增数据的处理及损失边界。
- 已有历史若暴露地图 Key，只记录路径和处置状态，不复制值；历史清理及轮换有单独执行安排。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 交付 MUST 检查当前代码、已进行迁移及验证记录，建立“原依赖—用途—替代能力—验收方式”对照；记录版本或快照、调用证据、处置、验证程度及复用边界。仅经对应成功和失败场景验证合格的成果可标已完成，其余为候选复用、待修复或待验证。
- **FR-002**: 应用 MUST 在无妙搭账号、平台 SDK、平台网关和平台数据库的 Windows 本机环境完成安装、构建、启动及已有业务，并由本机浏览器访问。安装、开发检查、构建与运行的直接、间接依赖及自动脚本不得要求平台能力；验收复核依赖清单、锁定清单、产物及实际请求。不要求 Linux、局域网手机访问或公网部署验收。
- **FR-003**: 系统 MUST 提供真实注册、重复账号拒绝、密码登录、退出及当前会话验证；密码不可明文保存或输出，凭证不可轻易猜测，注册及必要关联初始化全部成功或不留半完成结果。
- **FR-004**: 系统 MUST 执行公布的有限会话有效期及撤销规则，说明重新登录对旧会话的影响；缺失、伪造、到期、撤销凭证拒绝全部受保护操作。退出成功意味着服务端撤销及本地清理完成，未确认撤销按故事 2 场景 5 处理。
- **FR-005**: 系统 MUST 根据已验证账号、资源归属和有效的一对一照护授权关联确定访问范围，覆盖设置、长者、联系人、行程、围栏、地点、行踪、体征、告警及聚合结果的全部现有读写。无授权关系的账号之间隔离；长者对本人资料的授权访问不转移家属的管理归属。不信任客户端归属字段，不共用空归属，不泄露授权范围外资料。
- **FR-006**: 系统 MUST 使用独立的家属和长者真实账号，并建立服务端验证的一对一照护关联：每位长者及每个长者账号至多有一条有效关联，每条关联指定一个有权管理该资料的家属账号；家属账号可延续管理多位长者的已有流程。关联须有明确授权证据，不得仅凭姓名、手机号、资源编号或客户端声明建立；撤销或删除后访问立即失效。家属管理自身照护资料，长者仅可读取本人流程所需资料及执行逐项明定的本人操作；默认拒绝未列明操作和家属管理写入。规划须列出各数据类别的读写权限及关联建立/撤销验收，不新增多人协同或机构权限体系。页面切换、联系人登记及演示入口不产生授权。
- **FR-007**: 全部用户输入 MUST 在可信边界按适用的类型、必填、长度、格式、范围、允许值和字段关系验证，覆盖正文、路径、查询、请求头、嵌套、批量及语音转换结果。无效输入和伪造权限字段明确拒绝且不改数据；记录可选空值和未知字段规则。
- **FR-008**: 系统 MUST 完整持久化已有流程需保存的账号、归属、长者、联系人、行程、设置、围栏和地点；保留已有行踪、体征和告警的读取及数据含义。保存成功后刷新、重登、应用及数据库正常重启均读回同样内容，不升级模拟事件为真实服务。
- **FR-009**: 系统 MUST 保证账号唯一性和关联一致性，处理并发创建、重复操作、中途失败和已有删除规则，复合操作不留孤立资源。归属约束覆盖演示初始化，不依赖平台自动填充字段。
- **FR-010**: 前后端 MUST 在独立开发和构建后运行两种方式中完成真实请求、凭证传递及读写，保持受支持页面入口、流程和会话恢复。服务不可用、认证失效或保存失败给出正确反馈，不返回模拟成功。
- **FR-011**: 系统 MUST 区分认证、授权、验证、冲突、资源不存在和内部故障，并保持错误约定兼容。客户端识别实际错误结构，受保护失败不转演示成功，内部异常不向用户输出堆栈、凭证或敏感原因。
- **FR-012**: 系统 MUST 记录启动及配置失败、认证及退出结果、权限拒绝、输入拒绝、保存失败和迁移结果，包含时间、操作、结果和可关联的诊断标识；不记录密码、完整凭证、地图 Key 或多余个人资料，说明日志级别及输出位置。
- **FR-013**: 系统 MUST 提供配置清单，区分必需/可选项、默认值、加载优先级、环境及生效条件；必需项缺失或无效、数据库不可连接或结构不兼容明确失败。示例不含真实秘密，不依赖原平台变量。
- **FR-014**: 高德 Key MUST 由不提交的外部配置提供，不写入源码或提交历史；检查源码、产物处理方式及可访问历史但不输出值。若既有历史暴露，记录并安排轮换和清理，历史重写不默认为本次规格授权。地图缺失或失败须明确不可用，不阻断非地图流程。
- **FR-015**: 系统 MUST 保留两类显式选择且持续可辨识的演示：前端演示不写业务数据库，须说明其变化不代表服务端保存；演示账号使用真实本地密码认证、会话、授权和输入验证，将需保存的演示资料持久化并与普通业务资料隔离，现阶段可保留演示密码但不得绕过认证。模式切换不得带入其他模式的缓存、会话或授权；普通业务和演示账号的注册、登录、会话及保存失败不得自动转为前端演示成功。验证码仅为演示步骤，不代表手机号核验，不新增短信服务。模拟定位、叫车、求助、告警及通知不声明为真实，记录保存不代表真实服务执行。
- **FR-016**: 迁移 MUST 建立受支持契约及页面基线，覆盖调用方式、请求响应、字段含义、错误约定和可观察行为并回归验证。拒绝无效输入、越权等修复须记录影响，安全漏洞不定义为需保留的支持行为；确需破坏合法契约时另提版本及迁移方案供用户确认。
- **FR-017**: 平台专属组件及工具 MUST 在处置前确认实际使用，包括动态调用、类型引用和构建检查依赖；使用中能力替代并验收，确认无使用的才清理。模板中的通讯录、部门、群聊、名片、文件能力不自动成为新增业务。
- **FR-018**: 数据库变更 MUST 有可审阅的版本化迁移及回滚，覆盖空库初始化、使用本地测试数据验证后续版本升级、归属关联、独立运行所需字段类型及重复执行；本次不迁入或保留既有业务数据，不要求平台身份映射及旧数据导入工具。初始化须防止意外覆盖非空数据库，禁止通过清空数据代替升级或回滚。
- **FR-019**: 每次迁移回滚 MUST 说明触发条件、步骤、备份恢复前提、恢复策略、迁移后新增数据处理、完整性及应用兼容验证；不可逆转换有恢复路径。执行前核对前提，在隔离副本验证升级与回滚，未验证条件如实记录。
- **FR-020**: 交付 MUST 提供符合实际状态的本地说明，涵盖前提、锁定依赖安装、配置、数据库准备升级、开发和构建后启动、停止重启、地图不可用、演示、日志、故障及回滚；命令、目录、输入和预期输出具体且可复现。
- **FR-021**: 验收 MUST 记录版本环境、准确命令或操作、输入、预期和实际结果、脱敏证据及清理方式；覆盖全新安装、构建、启动、注册登录退出、会话失效、两账号全部资源隔离、角色越权、无效输入、重启保留、配置缺失无效、依赖故障、兼容和迁移回滚。静态、运行通过、失败和阻塞分开记录，脚本存在不等于通过。
- **FR-022**: 本次 MUST 只补齐已有业务的平台替代能力，不自动实现全部 PRD。`specs/001-audit-backend-gaps` 的全部 PRD 对照、主动代码检查、章程核对、发现分类及后端交接评估范围保持原样，初查和迁移验收不替代或声称完成该评估。
- **FR-023**: 规划实现 MUST 遵循现有服务职责并同步更新职责、输入输出、错误、权限、依赖和副作用文档；职责调整另行说明影响由用户确认。遵守默认围栏进出才上传位置、提醒不持续监听麦克风、手机原型不依赖手表基线。
- **FR-024**: 标准数据库运行路径 MUST 为 Windows 上的 Docker Desktop 本地 PostgreSQL 容器，应用在 Windows 本机运行；运行说明须面向初次开发者覆盖 WSL 2 和虚拟化前提、Docker 准备、数据库启动与就绪检查、持久卷、停止重启及备份恢复。Docker 或数据库未就绪时明确说明原因，不自动切换模拟存储；不要求 Windows 原生 PostgreSQL 安装方式验收。
- **FR-025**: 实施阶段 MUST 由代理检查运行环境并安装本次必需且缺失的工具及项目依赖，包括 Docker Desktop、WSL 2；复用已安装且兼容的 Node/npm，不因 PATH 未刷新而重复安装，不无故升级。工具与依赖从官方来源获取，记录来源及完整性或发布者校验结果；验证安装版本、WSL 2 状态、Docker 引擎和 Compose 可用性，并启动本地 PostgreSQL，验证数据库就绪和真实连接。可自动完成的步骤由代理执行；涉及 BIOS 虚拟化、系统重启、必须由用户操作的界面或工具权限限制时，说明已检查结果、不能自动完成的原因、具体用户操作和完成后的复检步骤，不擅自重启电脑，不将待操作步骤标为通过。后续 tasks.md MUST 将环境检查、缺失工具安装及验证列为应用实施和验收的前置任务；规划阶段仅更新文档，不立即安装。

### Key Entities *(include if feature involves data)*

- **本地账号**：唯一账号标识、密码验证信息、显示名和角色，区别于平台身份；包含普通账号和有明确演示标识、资料隔离的演示账号，两者均需真实本地认证。
- **会话**：账号身份、访问凭证、有效期及撤销状态，决定访问资格。
- **归属与授权关联**：家属管理的长者资料与独立长者账号的一对一授权关系，含授权证据、有效/撤销状态及角色操作范围；不由客户端自报，关联不改变资料管理归属。
- **已有业务资料**：长者、联系人、行程、设置、围栏、地点和已有行踪、体征、告警，保留含义关联，真实与演示来源可辨识。
- **依赖替代记录**：原依赖、用途、证据、替代、处置、验收与限制。
- **迁移恢复记录**：版本、测试数据集、备份前提、结果及归属和关联核对。
- **配置与诊断记录**：配置职责有效性、时间、操作、结果和诊断标识，不含秘密或多余个人资料。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 接手者仅凭说明在 1 个干净且无妙搭环境的 Windows 本机实例完成全新安装、构建、数据库准备及开发和构建后两种启动；本机浏览器访问的全部受支持入口与已有非地图流程通过，无平台访问要求。
- **SC-002**: 注册、正确/错误密码登录、重复注册、身份验证、退出、失效及到期会话场景 100% 符合预期；普通失败转演示成功次数为 0。
- **SC-003**: 2 个无授权关系的家属账号及至少 1 个独立长者账号覆盖全部受保护资源读写、聚合隔离和角色权限矩阵；关联前拒绝、授权后本人允许访问、家属管理越权拒绝及撤销后拒绝均通过，未经授权的跨账号泄露或越权成功次数为 0。
- **SC-004**: 每个输入入口的适用无效输入场景 100% 明确拒绝且不改数据；全部需保存资料经刷新、重登和至少 1 次应用及数据库重启后保持内容与关联一致。
- **SC-005**: 必需配置缺失、无效或依赖不可用场景 100% 明确失败并给出可操作说明；缺地图配置时全部非地图验收仍通过，用户可识别不可用原因。
- **SC-006**: 依赖对照和受支持契约清单覆盖已识别项的 100%，逐项有结果或阻塞；交付合格时必需项阻塞数为 0，模拟被声明为真实认证、定位、叫车、告警或通知次数为 0。
- **SC-007**: 从空库初始化的 1 份代表性本地测试数据完成版本升级及回滚，数量、账号归属、关联和字段含义全部一致；空库初始化及重复迁移通过，意外覆盖非空数据库或错误归属次数为 0；不要求真实旧数据迁入。
- **SC-008**: 接手者独立复现强制验收并据脱敏日志定位认证及保存失败；文档行为矛盾数为 0，新源码或提交含真实地图 Key 数为 0，已有历史检查有明确结果及必要处置。
- **SC-009**: 两类演示均有独立验收结果：前端演示写业务数据库次数为 0；演示账号真实认证及至少 1 次重启后的保存恢复通过；普通资料和演示资料之间的未授权读写次数为 0，模式切换引入旧模式资料或授权的次数为 0。
- **SC-010**: 实施记录覆盖环境检查、必需缺失工具的官方来源安装、兼容 Node/npm 复用、项目锁定依赖安装，以及 WSL 2、Docker 引擎、Compose、PostgreSQL 就绪和真实连接验证；各必需项均有实际结果。发现需用户操作的步骤时，逐项给出原因、具体操作与复检结果；未经用户明确指示的系统重启次数为 0。安装未完成或引擎/数据库未就绪时不宣称独立运行验收通过。

## Assumptions

- 规格、澄清及规划阶段仅更新文档和检查证据，不安装工具、不执行业务改动、数据库变更或部署；实施阶段按 FR-025 承担环境准备并提交实际验收。
- 功能目录为 `specs/002-remove-platform-dependency`；001 继续独立评估，不改资料和统计分母。
- Windows 本机运行环境、可获取官方依赖及 Docker Desktop 本地 PostgreSQL 为目标运行前提，必需工具不假设已由用户安装，实施代理按 FR-025 检查并补齐；Docker 使用 WSL 2 作为容器运行底座，不要求将项目或应用开发迁入 WSL。本次不包含 Linux 应用验收、Windows 原生数据库安装路径、局域网手机访问或公网部署。无妙搭不等于所有网络离线，地图及设备权限为可选依赖。
- 合法业务契约为兼容基线，越权、伪成功和丢失字段是待修复行为，不是产品承诺。
- 延续账号密码流程，演示验证码不证明手机号归属；新增的账号关联仅限本次已确认的一对一照护授权，不新增短信、找回密码、多人照护协作及复杂角色体系。
- 真实交付能力为安装构建启动、本地账号认证与会话、一对一照护授权、已有业务数据读写及独立运行支撑。前端演示不写业务数据库；演示账号的认证和持久化是真实的，但其演示资料与模拟服务不代表真实照护事件。地图在有效配置下可调用外部服务，本次不新增真实定位上报、事件检测、短信、告警投递或通知服务。
- 默认延续单一活动会话，重新登录替换旧会话；有限有效期具体值由规划确定、公开并验证，不指定实现机制。
- 本次从空库开始，不迁入现有平台或本地业务数据；测试数据覆盖本地账号归属及关联，用于版本升级和回滚验收。真实旧数据缺失不构成本次阻塞；未来旧数据导入须另行确认范围与映射规则。
- 初查基于有未提交改动的工作区；[source-context.md](source-context.md) 记录证据和限制。此次未运行安装、构建及业务验收，代码和历史日志不能证明当前工作区合格。
