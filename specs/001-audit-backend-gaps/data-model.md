# Phase 1: 评估记录模型

本模型只描述001评估资料及交付关系，不是未来业务数据库、路线响应模型或产品API。所有记录为Markdown表格/条目，不新增表或迁移。

## 标识及关联

| 实体/编号 | 必需字段 | 关系及校验 |
| --- | --- | --- |
| 材料SRC | 路径、日期、类型、版本/HEAD/dirty差异/hash、章程版本、缺失/限制 | 证据引用材料；本轮基线见research |
| 需求REQ | 独立用户结果、PRD页/章节、范围、角色、预期、验收、冲突ID、纳入/排除及理由 | 一需求可有多个能力环节；背景/例子不伪造要求 |
| 支撑行为SUP | 现有行为、代码位置、有效行为依据、适用约束 | PRD未规定项，不能填写虚假PRD页码 |
| 能力CAP | REQ/SUP、环节、前/后/跨端职责、现有行为、入口→服务→存储→接收方、状态、验证程度、证据ID、后端相关性、处置 | 多环节不可重复计为多条完整需求 |
| 证据EVD | SRC/代码符号或行号、场景/输入类型、方法、实际结果、日期、版本、原记录定位、复用范围、未覆盖/复核条件 | 区分代理运行/用户手动/静态；引用002而不复制改写 |
| 发现FND | 唯一ID、一个主分类、交叉标签、归属、现状/预期、REQ/章程/SUP依据、EVD、影响、优先级理由、确定度、复核条件 | 四主分类见下；交叉标签不增加发现数量 |
| 检查覆盖COV | FR-018领域、对象/符号/材料、方法、已检查范围、结果/FND、未覆盖及原因、限制 | 无发现也必记录，零发现不等于无缺陷 |
| 章程核对CON | I–VII或三基线、适用性、结论、EVD/FND、限制、批准例外出处 | 不适用须解释；现有代码与规划合规分开 |
| 处置DSP/交接HND | 可复用/必要修复/缺失/可选/端侧/未决、CAP/FND/REQ、复用边界或现状目标差异、职责、依赖/无依赖、順序、验收、兼容影响、迁移回滚要求、待确认ID | 可选待采纳，不能自动进入必做；后端与纯前端分开 |
| 决策DEC | 双方出处、问题、影响、已批准基线/暂缓决定或未解决、选项/代价、批准者/日期、依赖项 | 用户新功能要求用USR编号关联，不改原PRD或001规格 |

## 枚举及状态

- 范围：手机核心、PRD明确模拟、扩展、范围待定；支撑项单独统计。
- 实现状态：完整实现、部分实现、仅展示/模拟、未发现实现、待确认。
- 验证程度：已运行验证、仅静态证据、验证阻塞；复用运行需标“既有运行证据，本轮未重跑”及适用性。
- 主分类：需求缺口、代码缺陷、章程违反、可选改进；确认状态独立为已确认/未确认。
- 优先级：P1核心安全隐私/严重数据/阻断；P2核心完整性/必要可靠性维护；P3辅助扩展。确定度不是优先级。
- 章程：符合、有差异、明确批准例外、尚未验证；无迁移等不适用理由单列。
- 可选建议：待采纳→用户明确采纳；仅采纳才能成为后续范围，本轮仍不执行。
- 证据有效性：待核对→可复用/需增量/阻塞/被新证据校正；历史记录保留，被校正记录不计作当前成功。
- 发现疑点：未确认→证据支持后确认，或排除附理由；不能从“无环境”直接变已确认缺陷。

## 新路线调查记录（不是业务合同）

用户追加的首功能需求单独用USR-ROUTE编号关联交接。供应商调查记录含官方出处/查询日期、香港地区/方式、API与消费端区别、凭据/授权条件、返回字段及缺失、实际样本结果、覆盖限制、费用口径、许可/展示兼容和待选择方案。

无障碍证据按每段及接驳/入口/站台/换乘/车辆记录需求、来源、核查日期、适用条件、已知不可达或未知点。交付结论采用“已确认符合要求”“仅部分路段有依据”“信息不足，无法确认”；已知不满足另明确披露，不能强行并入合格。只有全程相关条件均有可信、适用且足够新证据才可确认；缺段不能借普通步行/少换乘/最短策略推导。

## 完整性和统计

ID唯一且所有引用可定位；空值写不适用或未知原因。PRD覆盖分母为已识别独立需求，排除项有依据；核心/模拟/扩展/待定分别列数量，不混算。完成数按唯一REQ且全部必要环节满足，不按CAP计数；有阻塞不能称运行验收完成。发现按唯一FND总数及主分类汇总，标签不重复计数。可选建议/未确认疑点/USR新增请求与PRD完成率分别统计。
