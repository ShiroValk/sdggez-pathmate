# Phase 1 Contract: 评估交付格式

这是评估资料对产品负责人、开发者与协调者的交付合同，不定义未来业务端点、表结构、路线协议或服务拆分。记录字段见 [data-model.md](../data-model.md)。

## 后续评估必须交付

| 文件（评估执行后生成） | 内容及通过条件 |
| --- | --- |
| report.md | 材料版本/日期/章程/范围、摘要、前三优先项、数量及分母、主要限制；摘要与明细一致 |
| requirements-matrix.md | 全部独立PRD需求来源/页码/角色/范围/预期/现状/环节/证据/状态/验证程度/后端相关性/处置/发现；排除项注明理由 |
| findings.md | 四类发现统一唯一ID、一个主分类及标签、依据/影响/优先级/验证/复现条件；疑点未确认，可选收益/代价/风险及待采纳 |
| inspection-coverage.md | FR-018十个检查领域全部有对象/方法/结果/未覆盖原因，含PRD外支撑行为；无发现也有记录 |
| constitution-review.md | 七原则三基线逐项适用性/符合差异例外未验/证据限制；例外需批准出处 |
| disposition.md | 可复用能力、必要修复、缺失能力、可选改进、端侧独立及无法判定分别列；按环节保留已有成果 |
| evidence-index.md | 原002证据定位、时间/版本/场景/工具类型、复用判断/范围限制、增量理由及结果/阻塞条件；失败历史保留 |
| decisions.md | 已批准三基线、Key暂缓原决定、新冲突双方出处/影响/选项/待决定问题；不得把已决定项重新当假设 |
| development-handoff.md | 各拟开发项依据/职责/依赖順序/验收/兼容/迁移回滚/未决；首功能为用户指定“多出行方式与无障碍路线支持”，供应商方案供选择 |

## 最低复核样本

需求对照抽查求助、位置安全、健康打卡各一条，PRD到全部环节及结论可追溯。账号/长者资料抽查正常、A/B隔离、撤权及未验证范围。PRD外支撑行为至少一项有正常/异常/覆盖限制。抽取一个必要修复和一个缺失项检验交接可读性；若确无此类发现，说明检查及原因，不为样本制造缺陷。

报告审阅者核查十类主动检查、七原则三基线、五条核心链路全部有记录；全部必要修复/缺失/拟开发项有依据、依赖、验收和风险。未参与评估者在15分钟内定位可复用基础、前三优先项及理由，记录审阅者/日期/结果；未执行则SC-006尚未验证。

## 路线交接专项合同

新增用户要求单列USR，不冒充PRD原文或扩展001已批准规格。须交付香港三方式实测计划、供应商及无障碍证据调查表、方案比较（覆盖/限制/成本/验证/许可），并明确“文档支持”“实际返回通过”“阻塞未验”区别。接口存在或消费App功能不能当可集成能力通过。

验收计划必须含香港实际起终点、步行/驾车/公交切换及旧响应迟到、公共交通步行接驳/上下车/线路/换乘、无路线、服务失败、无障碍信息不足及全程已确认样本。缺少已确认真实样本时保持待验，不用模拟填补；模拟异常测试与真实路线结果独立标识。

## 统计与拒收规则

SC-001–009逐项附计数或审阅记录。PRD覆盖率、实现比例、验证比例、发现数、可选数、新用户需求分别计，不把76/76实施任务数当002全部合格，也不把本轮规划当完整评估。

以下拒收：静态称运行通过、演示称真实通知、环境阻塞称未实现、历史Key暂缓隐藏、无依据必要修复、重复发现、可选默认必做、遗漏任一检查领域、普通路线称无障碍、切方式沿用旧路线、将未来API/表设计写入本评估合同。
