## 可复用基础与待核查差异

可复用候选：地图加载/搜索/有效目的地坐标、折线绘制、定位缓存、错误提示、002旧搜索结果隔离与用户Edge香港驾车个案。按research复用原范围，不重写认证/照护/持久化。

当前planRoute仅walking/driving；返回只有distanceM/durationS/points；现有路线页调用固定driving，步行由长者导航入口触发。未保留文本分段指引、未接公交、未见无障碍证据链。这些为已读取代码的静态范围观察，正式评估关联CAP/FND；不是运行失败声明。现有catch返回null将服务错误与无路线归并，应评估其用户影响及兼容，不直接改实现。

## 依赖及建议顺序

1. 完成001需求/代码/契约评估，确认地图身份切换、资源释放及路线状态边界；有已证实P1安全隐私/数据阻断先处理。修复与缺失分列，不以“首功能”跳过阻断问题。
2. 先完成香港供应商能力与无障碍数据调查，以及真实样本验证计划；现有Key暂缓不变。若高德能力不足，提交可审阅替代方案让用户选择后再定后续供应商。
3. 明确具体无障碍需求维度、证据新鲜度/确认口径、许可/坐标/地图展示兼容、配额预算和无可信数据的显示方式。不得用未决定的供应商或自行数值推进依赖设计。
4. 对新建功能另行specify/plan，关联USR与001发现；再安排最小可验收三方式闭环、公交分段和无障碍证据呈现。不能把未知无障碍能力默认为已实现或把它无声排除验收。

当前职责：client地图适配处理供应商调用/绘制，engine负责用户选择及展示，shared为受支持契约；Auth/Elder/Family已有职责保留。是否需要服务端代理、数据融合或新服务由后续规划论证；本阶段不作职责分配变更。路线偏好是否持久化也不预设；若后续需要新数据/迁移，必须提交兼容及回滚计划。

此前隐私控制/配置同步建议撤回“首功能”地位，仍作为001必评领域及潜在依赖/缺口记录；不自动扩大本次路线开发范围。

## 后续业务验收结果

| 场景 | 必须观察到的结果/证据 |
| --- | --- |
| 香港三方式 | 多组真实公共地点返回对应路线、时间、距离、分段指引；标供应商/查询时间/真实或模拟；接口存在不算通过 |
| 方式切换与竞态 | 步行→驾车→公交及反向/快速切换均重新规划；新请求待定/失败时旧折线/摘要/指引不冒充当前结果；旧方式迟到响应不覆盖 |
| 公交换乘 | 实际样本含步行接驳、上下车站名、线路、换乘顺序，字段缺失明确展示不完整，不编造 |
| 无路线及服务失败 | 真无路线与超时/权限/配额/网络等失败区分，可操作反馈；不沿用旧方式路线或假距离/时间 |
| 无障碍信息不足/部分 | 未覆盖路段、缺站点或车辆数据、过期/冲突/设施不可用明确提示；不显示已确认 |
| 已确认无障碍 | 全程满足所选要求，街道/入口/设施/站点/车辆/接驳/换乘都有可信适用证据，含日期和条件；无真实合格样本则待验，不用模拟补 |
| 隐私与模拟边界 | 不将公共测试点或本机起点当远端长者追踪；关闭共享不被新功能绕过；模拟失败/路线只验显示逻辑，不计真实香港覆盖 |
