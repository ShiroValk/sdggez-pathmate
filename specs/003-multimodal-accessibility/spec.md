# Feature Specification: 多出行方式與無障礙提示

**Feature Branch**: `feat/003-multimodal-accessibility`

**Created**: 2026-10-11（Asia/Hong_Kong）

**Status**: Implemented with explicit limitations（純邏輯與受控UI已驗；真實高德HTTP與本機DB回歸已取得；真實瀏覽器、資料許可／回放仍有限制，詳verification）

**Input**: User description: "根據現在完成的部分，建立下一編號的新功能規格。實作多出行方式與無障礙提示。真實、靜態資料、模擬與未完成內容明確區分。不以實地核驗、全程已確認樣本或長期維護作為演示前置。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 選擇三種出行方式並閱讀相應路線 (Priority: P1)

作為長者或演示者，我希望為同一起終點選擇步行、駕車或公共交通，看到該方式的路線、預計時間、距離及分段指引，以說明不同出行選擇的用途。

**Why this priority**: 現有應用只有分散的步行與固定駕車入口；三方式選擇及可閱讀指引是本功能的主要演示閉環。

**Independent Test**: 用一組明確選定的香港公共起終點，依次選三方式，核對各自的方式名稱、路線與摘要，不依賴無障礙資料完整或實地證據。

**Acceptance Scenarios**:

1. **Given** 起終點已明確選定且可用，**When** 選步行或駕車並取得有效結果，**Then** 顯示相應路線、供應商預計時間與距離、有序文字指引及結果來源類型，不把估計稱為實際測量。
2. **Given** 相同起終點，**When** 選公交並取得有效方案，**Then** 按實際順序呈現步行接駁、上下車站、線路、乘車段及換乘；同段備選線路不被當作連續換乘。
3. **Given** 方案缺少時間、距離、指引或幾何資料，**When** 查看結果，**Then** 缺少部分明示「資料未提供」，可用內容仍可閱讀，不補造零值、路段或線條。
4. **Given** 某方式尚未接入或不可用，**When** 選該方式，**Then** 明示未完成或目前不可用及原因；提供模擬方案時先明示模擬性質，不靜默改成其他方式。

### User Story 2 - 切換方式與失敗時看清目前結果 (Priority: P1)

作為使用者，我希望切換方式、起終點或重新規劃時，只看到當前選擇的結果，並能分辨沒有路線和查詢失敗，避免誤讀上一條路線。

**Why this priority**: 001 已確認等待或失敗時舊線與摘要可能殘留，服務錯誤與無路線混淆；新增方式會放大這些問題。

**Independent Test**: 在既有步行／駕車流程以明示延遲與故障測試切換、重試和離頁；即使公交與無障礙資料未具備，也可驗證舊結果不冒充目前结果。

**Acceptance Scenarios**:

1. **Given** 已有駕車結果，**When** 切換步行、公交或修改起終點，**Then** 立即停止把舊折線、摘要、指引及無障礙結論當作當前結果，呈現目前正在查詢的選擇。
2. **Given** 快速切換且早期結果較晚返回，**When** 接收結果，**Then** 只有最新選擇可更新畫面；離頁、退出、切換身份或演示模式後，舊結果亦不回填。
3. **Given** 查詢正常完成但沒有可用路線，**When** 查看結果，**Then** 明示「找不到此方式路線」，保留起終點與方式供修改。
4. **Given** 網路、權限、配額、服務或回應格式異常，**When** 查詢失敗，**Then** 明示查詢失敗及重試／修改入口，不聲稱該路線不存在，也不顯示模擬成功。
5. **Given** 定位拒絕或地點沒有有效坐標，**When** 準備規劃，**Then** 保留輸入並提示明確選擇有效公共起點／終點，不使用虛構位置或猜同名地點。

### User Story 3 - 閱讀有依據及缺口明確的無障礙提示 (Priority: P1)

作為需要一般輪椅出行資訊的使用者，我希望啟用無障礙需求後，了解與選定路線有關的設施資料、哪些環節缺乏依據及是否需要職員協助，以看懂資訊能支持到哪一步。

**Why this priority**: 普通路線成功不證明輪椅可達；演示的價值在於把有限資料和未知條件說清楚。

**Independent Test**: 對一個已選路線提供可追溯的局部靜態資料與缺口，檢查部分／不足結論、來源及協助條件；不要求完整無障礙路線、實地核驗或持續更新。

**Acceptance Scenarios**:

1. **Given** 啟用一般輪椅需求且只有部分相符設施資料，**When** 查看提示，**Then** 顯示「僅部分路段有依據」、來源與日期，以及未涵蓋的街道、入口、站內、站台、車輛或接駁環節。
2. **Given** 沒有可對應該路線的資料，**When** 查看提示，**Then** 顯示「資訊不足，無法確認」，不因普通步行成功、少換乘或最短距離標為輪椅可達。
3. **Given** 資料提及需港鐵職員提供便攜斜板，**When** 查看相關乘車段，**Then** 說明協助需求及安排條件；未有適用的協助可獲得性依據時保持部分或不足，不暗示已預約。
4. **Given** 資料過期、不含日期、互相衝突或有已知不可達環節，**When** 查看結論，**Then** 分別揭示限制；已知障礙直接標示，不被其他可用設施或未知資料掩蓋。
5. **Given** 全程任一必要環節仍未知，**When** 匯總路線，**Then** 不出現真實「已確認符合要求」；模擬完整確認的展示邏輯亦標為模擬，不計真實樣本。

### User Story 4 - 在演示中辨識能力與資料邊界 (Priority: P2)

作為黑客松觀眾或接手者，我希望在演示及交付說明中辨識真實查詢、靜態資料、模擬與未完成部分，理解哪些功能有用、哪些限制仍存在。

**Why this priority**: 混合來源可以展示故事，但不能把模擬或資料目錄包裝為完整服務已通過驗收。

**Independent Test**: 查看含四類內容的演示畫面及交付範圍表，逐項核對標識、來源與驗證記錄，毋須全程已確認樣本。

**Acceptance Scenarios**:

1. **Given** 真實供應商路線搭配靜態設施資料，**When** 查看結果，**Then** 路線與設施分別標明來源類型，靜態資料不被稱為即時狀態或實地核驗。
2. **Given** 進入顯式模擬情境或播放已保存的過去查詢結果，**When** 展示路線，**Then** 模擬／靜態回放標識保持可見，真實查詢歷史與當次未調用分開說明。
3. **Given** 一項能力做不出來，**When** 查看交付說明，**Then** 有未完成／暫緩條目、原因、影響及目前可用替代展示，不稱全功能完成或無限補驗。
4. **Given** 全程已確認真實樣本為0且沒有維護人員，**When** 完成受限演示，**Then** 仍可交付已實作及已驗證部分，明示樣本數與一次性資料邊界，不要求實地、全程樣本或長期維護才能演示。

### Edge Cases

- 公交有多方案，同一乘車段有備選線路：方案與備選分開，換乘按實際乘車段順序計算。
- 公交無換乘或部分路段沒有幾何：如實呈現，不為故事捏造換乘或完整折線。
- 極短接駁（如1米）或一般地點而非指定入口：明示粒度不足，不推斷站台、入口或末段可達。
- 等待、失敗、無路線及重試：舊摘要、指引與無障礙提示不能殘留成目前結果。
- 已知階梯／設施故障與其他可用資料並存：已知障礙直接披露，部分依據不等於可完成出行。
- 資料只證明設施／車隊一般特性：未對應路線、入口、班次或車輛時僅列背景，不升格為路段已確認。
- 資料日期缺失或超出其有效期：明示日期未知或過期，不自行指定統一有效天數。
- 免費額度耗盡或資格／許可未確認：明示限制或採用已標識靜態／模擬展示，不自動付費。
- 定位拒絕、零坐標及不完整輸入：合法零坐標與缺少坐標區分，明確選定起終點後才規劃。
- 切換身份、長者、真實／演示上下文或離頁後遲到回應：不回填、不外洩先前身份內容。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 在主要行程路線演示入口提供步行、駕車、公共交通選擇並顯示當前方式。既有其他導航入口可保留默認方式，但 MUST 遵守當前結果與失敗提示規則。
- **FR-002**: 每次有效規劃 MUST 對應明確選定的起終點及方式；同名地點或無有效坐標時要求明確選擇，不偽造位置。定位不可用時 MUST 可選公共起點繼續演示。
- **FR-003**: 有效結果 MUST 展示方式、起終點、路線、供應商預計時間、距離與有序文字指引；缺少字段 MUST 明示未提供，不補造默認數字或幾何。
- **FR-004**: 公交 MUST 依選定方案順序展示步行接駁、上下車站、線路、乘車及換乘；同段備選線路 MUST 與連續乘車段區分，無換乘時不得捏造。
- **FR-005**: 方式或起終點改變、重新規劃時 MUST 立即使舊路線、摘要、指引及無障礙結論失去當前結果地位並顯示等待；失敗或無路線不得重新採用舊結果。
- **FR-006**: 遲到結果 MUST 不得覆蓋最新選擇，也不得在離頁、切換帳號／長者或真實／演示模式後回填；重試 MUST 採用當前起終點與方式。
- **FR-007**: 系統 MUST 區分查詢中、成功、正常查詢無路線、查詢失敗及功能未完成；失敗保留選擇並提供重試／修改入口。已知原因按實際資訊提示，未知原因不得猜測。
- **FR-008**: 系統 MUST 提供可選的一般輪椅需求提示；此選擇表示評估資料與條件，不表示供應商已有輪椅專用路線。關閉需求不得改變普通路線真實性。
- **FR-009**: 無障礙提示 MUST 區分「已確認符合要求」「僅部分路段有依據」「資訊不足，無法確認」。沒有真實全程已確認樣本時不要求展示真實已確認結果；已知不可達另明確標示。
- **FR-010**: 真實「已確認」MUST 有對所選路線全程與一般輪椅需求適用的可信證據，涵蓋所需街道／過路、入口、升降機／坡道、站內／站台、車輛、上下車、接駁與換乘，以及日期與協助條件。必要環節未知、過期、衝突或已知不可達時 MUST 不作此結論。實地核驗不是唯一證據形式，也不是演示前置。
- **FR-011**: 部分／不足提示 MUST 列出資料支持範圍與未涵蓋環節；只有一般設施目錄或車隊特性而未匹配路線時 MUST 列為背景，不稱整段已確認。
- **FR-012**: 每項無障礙資料 MUST 有來源、資料類型、適用地點／環節、發布／更新日期（缺失則明示）、查閱日期、適用條件及限制；靜態資料不宣稱即時正常或已實地核驗。
- **FR-013**: 系統 MUST 揭示過期、日期未知、衝突與已知障礙；新鮮度或適用性不足時維持部分／不足，不設定無来源依據的統一有效天數或承諾持續監控。
- **FR-014**: 需職員協助便攜斜板的環節 MUST 顯示協助需求及安排條件；沒有可信適用的可獲得性依據時不得稱已確認、已預約或協助已到位。本功能不代聯繫或預約。
- **FR-015**: 系統 MUST 不以普通步行成功、最短、少換乘或駕車方案替代全程無障礙證據；啟用需求本身不保證重新規劃出輪椅適用路線。
- **FR-016**: 路線與資料 MUST 各自區分真實當次查詢、靜態資料／歷史回放、顯式模擬及未完成；混合結果 MUST 分項標明，不只用頁面總標籤代表全部。
- **FR-017**: 模擬路線、已確認狀態或失敗情境 MUST 持續顯示模擬標識，驗證僅證明展示邏輯，不計入真實香港返回、全程確認或實地核驗。真實服務失敗不得靜默回退為模擬成功。
- **FR-018**: 演示 MUST 沿用香港主要地區與尖東／尖沙咀文化設施候選，按資料選少量公共起終點，不聲稱整區、全港或所有輪椅覆蓋。含換乘公交情境可用既有真實樣本核對或明示回放，不要求每條候選都有換乘。
- **FR-019**: 交付說明 MUST 列出能力、資料類型、驗證方式／結果及未完成／暫緩原因與影響，將真實運行、靜態審查、模擬驗證分開。可有依據地暫緩未能實作部分，但不得把暫緩當通過或默默刪除三方式目標。
- **FR-020**: 受限演示交付 MUST 不以實地核驗、至少一條全程已確認真實樣本、定期更新／長期維護或正式服務部署為前置。真實全程樣本為0可如實交付，不代表原完整無障礙能力驗收通過。
- **FR-021**: 調用 MUST 沿用既有高德及已批准補充資料方向，核對適用免費資格、額度及資料使用條件；無可用免費條件時說明限制，不自動充值、啟用付費超額、續訂或採用未批准替代服務。
- **FR-022**: 路線功能 MUST 保留既有權限、身份隔離及位置邊界；公共測試點與本機規劃不作遠端長者追蹤，不新增週期上傳、不繞過共享關閉、不持續監聽麥克風、不依賴手表。
- **FR-023**: 新功能 MUST 保持受支持行程、地點、設定及角色流程相容；本階段不要求持久化偏好、新增資料庫或改變服務職責。確需不相容契約或職責調整時先提具體影響供用戶確認；確需遷移時附回滾計劃。

### Key Entities *(include if feature involves data)*

- **出行選擇**：明確起終點、方式、一般輪椅需求、當前身份／演示上下文，決定可展示哪次結果。
- **路線方案**：對應選擇、供應商、取得時間、來源類型、預計距離／時間、可用幾何及有序路段；字段可缺失但不偽造。
- **路段與交通選項**：接駁或乘車段、起終站、線路、同段備選、換乘順序及指引，支持閱讀與局部資料對應。
- **無障礙依據**：來源、類型、對應入口／設施／路段或僅背景、資料／查閱日期、條件、支持範圍與缺口，獨立於普通路線來源。
- **無障礙結論**：需求、全程／部分／不足狀態、已知障礙及協助條件，附對應依據，不由普通路線估計自動得出。
- **交付狀態條目**：能力、已實作／未完成／暫緩、真實／靜態／模擬證據、原因與影響；資料類型與功能完成狀態分開記錄。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 至少一組明確香港公共起終點能在主要入口完成三方式選擇，每方式有對應路線、時間、距離及有序指引，個別缺資料明示。逐方式記錄真實、靜態回放或模擬；未完成方式保持未達標，不以其他方式替代。
- **SC-002**: 至少一個含換乘公交情境呈現首末接駁、上下車站、線路及換乘順序；同段備選誤計換乘為0。註明當次真實查詢或歷史回放，模擬不計真實覆蓋。
- **SC-003**: 正反三方式切換、快速切換遲到、修改起終點、離頁／身份／模式變更及重試各情境中，舊路線、摘要、指引或結論冒充目前結果次數為0；人為延遲註明為測試控制。
- **SC-004**: 無路線、服務失敗、缺坐標、定位拒絕4類情境均顯示對應反饋並保留可修改輸入，偽造成功／默認距離時間次數為0；模擬故障分列。
- **SC-005**: 覆蓋局部依據、完全不足、日期未知／過期、資料衝突、已知不可達、職員協助6類情境，均披露範圍與缺口；未知情况下真實「已確認」誤標為0。可明示模擬難以取得的邊界，不要求真實完整樣本。
- **SC-006**: 演示中100%的路線結果、設施資料、模擬情境與未完成入口可識別類型；所有無障礙資料可查來源、日期或缺失說明、適用範圍與查閱日期。
- **SC-007**: 交付範圍表涵蓋23項功能要求，區分通過、未驗證與未完成／暫緩；每個暫緩項有原因及影響，真實全程已確認樣本數如實記錄，可為0。
- **SC-008**: 一次演示可講明「選方式→讀路線／公交段→看無障礙依據與缺口→看失敗或不足反饋」；交付條件中實地踏勘、全程確認樣本、長期維護必需項為0。部分暫緩時只聲明可演示範圍，SC-001等未達項保留。
