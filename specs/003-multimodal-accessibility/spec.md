# Feature Specification: 多出行方式與無障礙提示

**Feature Branch**: feat/003-multimodal-accessibility

**Created**: 2026-10-11（Asia/Hong_Kong）
**Revised**: 2026-10-12，R2 普通入口真實使用體驗
**Status**: Incremental revision；R1完成記錄保留，R2另驗。

**Input**: 修訂現有003：沿用普通入口、頁面與流程；香港公共地點和行程只作輸入預設，路線、地圖、搜尋及公交用現有真實服務；演示業務資料在本頁記憶體，刷新恢復預設，普通狀態照常保存；移除來源／模擬／回放控件，不讓用戶輸入經緯度；提供易讀按鈕、時間、距離、地圖及按需展開指引。

R2取代R1將來源選擇、模擬情境、歷史回放及坐標輸入放入產品頁的要求。T001–T053已完成標記及E01–E10保留為歷史，不作R2新頁面驗收；先前文件可由checkpoint 3894916查閱。不建立新功能編號。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 從普通入口查看真實三方式路線 (Priority: P1)

長者從首頁搜尋、常用地點、既有行程或返家直接進同一導航頁，沿用目的地，選起點與方式後閱讀地圖和指引。

**Why this priority**: 黑客松展示普通出行流程，無專用控制台或重複選點。
**Independent Test**: 從首頁公共預設地點進入，選公共起點，依次完成三方式當次真實查詢；定位不是前置。

**Acceptance Scenarios**:

1. **Given** 普通入口已有目的地，**When** 點導航，**Then** 直接進同一頁並帶入名稱／可用位置；只有文字且沒有明確對應時讓用戶明選候選。
2. **Given** 明確起終點，**When** 規劃步行、駕車或公交，**Then** 取得真實供應商結果、底圖、易讀時間／距離與指引；公交接駁、上下車、線路、備選與換乘依實際順序。
3. **Given** 手机使用，**When** 選點，**Then** 只用名稱搜尋、定位或預設，沒有坐標／來源／模擬／回放控件或新增導航層級。
4. **Given** 缺字段／幾何或地圖失敗，**When** 查看，**Then** 缺失明示、不補造；地圖失敗仍保留已取得真實指引與地圖重試。

### User Story 2 - 切換與失敗只顯示目前結果 (Priority: P1)

使用者修改地点、方式或離頁時，舊內容失效；失敗可重試／改地点，不返回假路線。

**Why this priority**: 既有結果不可冒充最新選擇。
**Independent Test**: 自動化控制遲到、無路線、傳輸失敗與定位拒絕；產品不提供故障情境選單。

**Acceptance Scenarios**:

1. **Given** 已有路線，**When** 修改、搜尋、定位或重試開始，**Then** 立即清除舊線、摘要、指引與結論。
2. **Given** 舊回應遲到，**When** 已改選擇、離頁、身份／長者／演示狀態，**Then** 舊成功、無路線與失敗均不回填。
3. **Given** 無路線或服務失敗，**When** 查看，**Then** 分辨結果，保留選擇，提供重試／改地点，不改方式或返回模擬成功。
4. **Given** 定位拒絕或候選不明確，**When** 選點，**Then** 可改公共起點／明選候選，不猜同名地點或虛構位置。
5. **Given** 同次查詢有多方案，**When** 方案／同段備選往返或切輪椅需求，**Then** 不重查，舊評估不因返回同一選項而被接受。

### User Story 3 - 看有依據的無障礙提示 (Priority: P1)

一般輪椅使用者直接看見有依據的障礙與必要協助，資料不足時有簡短說明，不選結論。

**Why this priority**: 路線成功不能代替可達依據。
**Independent Test**: 真實路線與實際可用資料配合；局部、未知／過期、衝突、障礙、協助與完整分支用自動化測試覆蓋。

**Acceptance Scenarios**:

1. **Given** 只有背景連結或無適用依據，**When** 啟用需求，**Then** 簡短說明不能確認全程，來源／缺口按需展開，不稱設施當次正常。
2. **Given** 適用障礙或必要協助，**When** 查看，**Then** 直接顯示條件，詳細依據與日期可展開，未安排不稱已預約。
3. **Given** 日期未知／過期／衝突或必要環節未知，**When** 評估，**Then** 保留限制、不保證全程可達；用戶只能選需求，不能選結論。

### User Story 4 - 同流程使用不保存的演示業務資料 (Priority: P1)

講解者使用香港公共地點與行程預設，在普通流程新增／編輯而不改資料庫；普通帳號仍能保存。

**Why this priority**: 演示與普通使用應共用功能，不需要用戶選儲存方式。
**Independent Test**: 演示修改跨頁／切長者保留，刷新恢復預設；普通合成帳號保存後可重讀。

**Acceptance Scenarios**:

1. **Given** 演示狀態，**When** 新增／編輯／刪除業務資料，**Then** 只更改本頁記憶體，跨頁／切長者保留，刷新恢復預設，無儲存設定。
2. **Given** 普通狀態，**When** 同樣操作，**Then** 原保存、驗證、角色與錯誤流程保持。
3. **Given** 演示公共預設，**When** 搜尋、規劃或看地圖，**Then** 使用真實服務；只保留簡短「演示資料不保存」提示。
4. **Given** 演示登入或刷新，**When** 進頁面，**Then** 使用同一普通流程，不增加控制台或另一套導航。

### Edge Cases

- 同名候選以名稱／地區／地址供明選，不顯示坐標；公共POI不等於已核驗入口。
- 路線成功／地圖失敗分開，無假底圖；缺幾何不得跨缺口連線。
- 同段備選不算換乘，極短接駁不作可達依據。
- 搜尋／定位／快切／離頁／模式切換立即失效，遲到成功和錯誤都隔離。
- 演示會話認證／登出可用服務，业务修改不寫DB，不擴普通權限。
- 演示切長者再切回保留頁內修改，刷新只恢復預設。
- 配額／服務不可用時重試或改地点，不自動付費、換服務或假成功。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: MUST 從既有首頁搜尋、常用地點、行程及返家進同一導航頁，提供三方式；不增獨立演示控制台或多層入口。
- **FR-002**: MUST 用名稱搜尋、定位或預設明選起終點；不讓普通用戶輸入經緯度，已有目的地／位置直接帶入，未匹配時明選候選。
- **FR-003**: 真實結果 MUST 顯示底圖、所提供路線、易讀時間／距離及有序指引；詳細可展開，缺值不偽造，地圖／路線失敗分開。
- **FR-004**: 公交 MUST 按實際順序呈現接駁、站點、線路、乘車、換乘與同段備選；備選不算連續換乘，切方案不重查。
- **FR-005**: 修改、搜尋、定位或重試開始前 MUST 使四類舊內容失效，失敗不恢復舊結果。
- **FR-006**: 遲到成功、無路線與失敗 MUST 不覆蓋新選擇、身份／長者／演示／離頁上下文；重試採目前選擇。
- **FR-007**: MUST 區分等待、成功、無路線、查詢失敗及地圖失敗；保留選擇，提供重試／改地点，不猜未知原因。
- **FR-008**: MUST 提供一般輪椅資訊需求，只改評估、不暗示專用路由或重發普通路線。
- **FR-009**: MUST 根據實際依據得出全程確認／局部／不足，用戶不能選結論；已知障礙直接顯示，無真實全程樣本仍可交付有限能力。
- **FR-010**: 真實確認 MUST 有全部必要街道、入口、站內、月台、車輛、上下車、接駁／換乘及日期／協助條件的可信適用依據；任一必要缺口不得保證可達。
- **FR-011**: MUST 簡短呈現支持範圍與不足，詳細可展開；未匹配的目錄只作背景。
- **FR-012**: 依據 MUST 可查來源、類型、適用環節、來源日期或未知、查閱日、條件與限制；靜態非即時正常。
- **FR-013**: MUST 披露日期未知／過期／衝突及障礙，不設無依據統一有效期或維護承諾。
- **FR-014**: 必要職員協助 MUST 直接顯示條件；無可獲得性依據不稱確認／預約／已到位，不代聯繫。
- **FR-015**: MUST 不以普通路線成功、最短、少換乘或駕車保證輪椅可達。
- **FR-016**: 產品路線、地圖、搜尋與公交 MUST 用既有真實服務；來源在結果／資料詳情按需查，預設輸入與真實返回分開記錄。
- **FR-017**: MUST 刪除產品來源、模擬情境、歷史回放及選結論控件，不能另建頁保留；合成邊界只在測試，真實失敗不回假路線。
- **FR-018**: MUST 優先少量香港公共起終點及行程作輸入快捷方式；不扩全港或無關能力，不把預設當核驗入口。
- **FR-019**: 交付 MUST 分列真實運行、靜態審查、受控測試及未完成限制，保留R1證據／完成記錄，不把R1當R2驗收。
- **FR-020**: MUST 不以實地、全程真實已確認樣本或長期維護作前置；真實confirmed可為0，有限交付不冒充完整服務。
- **FR-021**: MUST 沿用已批准服務與現有Key，不自動充值、付費超額、續訂或新服務；私有權益限制如實記錄，既有使用授權保持。
- **FR-022**: MUST 保留身份、照護權限及本機位置邊界，不加遠端追蹤、周期上傳、持續錄音或手表依賴。
- **FR-023**: 演示新增／修改／刪除業務资料 MUST 只在本頁記憶體，刷新恢復預設，無儲存方式設定；普通狀態保留原持久化及受支持契約，不變服務責任或遷移。

### Key Entities

- 地點選擇：名稱、明確位置及搜尋／定位／公共預設的選取依據，位置不由用戶手填。
- 路線批次與呈現：真實查詢、多方案、分段幾何、指引、備選與缺值；選擇不改原批次。
- 無障礙依據與結論：適用範圍、日期、障礙與協助，獨立於路線成功。
- 頁內演示业务資料：預設與本頁修改，按長者隔離、刷新重建。
- 交付狀態：R1歷史、R2當次證據與限制，真實／靜態／受控分列。

## Success Criteria *(mandatory)*

- **SC-001**: 普通入口一組香港公共預設點完成三方式當次真實查詢、地圖及指引；缺值明示，未完成方式不以假路線補足。
- **SC-002**: 一個真實公交結果有序接駁與乘車；換乘參照另記，備選誤計換乘0，測試不計真實覆蓋。
- **SC-003**: 修改、正反／快切、離頁、身份／長者／演示與重試四類舊內容誤標0；方案／備選往返路線請求增量0。
- **SC-004**: 無路線、服務失敗、未明選、定位拒絕皆可改／重試，偽成功或缺值造數0；地圖失敗不冒充路線失敗。
- **SC-005**: 自動化涵蓋局部、不足、日期未知／過期、衝突、障礙及協助，真實不足誤confirmed0，產品選結論控件0。
- **SC-006**: 390px手機來源／模擬／回放／坐標控件與新增控制台0，步驟／來源按需展開，可用鍵盤与清楚按鈕操作。
- **SC-007**: 23FR及8SC有R2對應檢查與證據，保留歷史與限制；每筆結果／依據可追溯，真實confirmed如實記錄。
- **SC-008**: 演示业务新增／編輯／刪除DB寫入0，跨頁／切長者保留，刷新恢復；普通合成帳號保存後可重讀。實地／全程確認／維護前置0。

## Assumptions

- 使用者2026-10-12九項方向是R2有效決定；移除產品模擬不改章程對測試／交付真實性區分。
- 普通入口為既有首頁、搜尋、地点、行程及返家；既有演示登入可進相同頁面。
- 公共預設不是GPS、核驗入口或無障礙依據；真實服務失敗如實顯示。
- 刷新可保留非業務的登入／模式識別，重新建立預設；业务修改與私人位置不得持久存儲。
- 現有Key已獲使用授權，私有免費類別／額度／期限／付費設定未独立核查，不宣稱永久免費。
- 沿用[章程v1.0.1](../../.specify/memory/constitution.md)及001/002權限與位置邊界，不增叫車、救援、通知、健康、預約或手表真實能力。
- 設施正文許可或適用依據不足時只用簡短不足與官方來源詳情，不複製未授權內容。
