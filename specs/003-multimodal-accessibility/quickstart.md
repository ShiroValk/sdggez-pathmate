# Quickstart: 003 普通入口手动核验（R2）

指南更新：2026-10-13。运行参考值来自2026-10-12验收，不是今天重新查询的结果。R1来源／模拟／回放／坐标操作指南已撤销；历史见commit `3894916`，E01–E10保留，不作为R2当次通过证据。

按以下8步从普通入口核验。**演示身份只影响业务资料保存；路线、地图、搜索和公交仍使用现有真实高德服务。**

## 1. 启动并进入普通首页

先尝试打开[本机应用](http://127.0.0.1:3000/memopath)。如果应用没有运行，在原Docker数据库服务启动后执行：

```powershell
Set-Location C:/Users/RedV/Documents/Code/sdggez-pathmate/existing_app
npm.cmd run dev
```

再打开[开发入口](http://127.0.0.1:5173/memopath)。沿用Node24、现有依赖、数据库与Key；已运行的服务直接复用，不重新迁移或重建数据库。终端需保持运行。

选择「長者端」→「演示登入」。

**预期：**进入原有首页，看到简短的「演示資料不保存」及香港公共地点快捷按钮，没有独立演示控制台。

## 2. 核验三种真实出行方式

首页点「聖德肋撒醫院」，应直接进入同一导航页：

- 目的地已带入医院，起点已带入「香港理工大學」。
- 不需要输入经纬度，也不需要先允许定位。
- 依次点「步行」「駕車」「公交」，等待各次结果。切换到不同方式会用目前端点查询；要重新查询当前方式，点「查看路線」。

**预期：**每种方式展示真实底图、当次路线、起终点，以及易读的时间和距离。展开「查看詳細指引」后能看到对应步骤；未提供字段明确显示缺失，不造数值或几何。

10月12日验收参考值：步行约44分钟、驾驶约11分钟、公交约35分钟。**当前数值可以变化，不要求完全相同。** 某种方式失败时记录实际提示，不能用其他方式成功代替该项通过。

## 3. 核验公交顺序与换乘

医院公交结果展开指引，检查上车前步行→乘车→下车后步行的顺序，以及上下车站点和线路。

再把目的地选为「香港國際機場T1出發」，保持公交方式，点「查看路線」。此前返回屯马线→东涌线→S1，3个乘车段、2次换乘；核对当次结果的顺序与换乘接驳。如果当次无路线，应明确提示，不能出现替代假路线。

如有多个方案或「此段其他線路」，切换后应更新指引，同段备选不能增加一次换乘。

**请求检查：**开发者工具Network选择 **All**，筛选 `amap.com/v3/direction/`。方案／同段备选切换不应新增路线请求；地图瓦片加载可以有请求。当前JSONP会以script请求出现，仅看Fetch/XHR会漏掉。

## 4. 核验名称搜索与目的地带入

输入「香港科學館」→「搜尋目的地」：

- 应出现带地区、地址的真实候选，由你明确选择，不默认取同名第一条。
- 修改名称后，旧路线线条、摘要、指引和无障碍结论应立即清除；底图可以保留。
- 未选择候选就点「查看路線」，应提示先选地点，不沿用旧地点坐标。

再从家属端已有行程的「導航前往」进入，检查目的地直接带入，仍使用同一导航页。已有唯一匹配公共点不需要重复搜索；没有确定位置时需明选候选。常用地点／行程沿用原驾驶意图，首页搜索／返家沿用原步行意图。

## 5. 核验无障碍提示

查询成功后勾选「需要輪椅出行資訊」：

- 当前没有全程适用设施依据，应显示资料不足、未能确认全程轮椅可达。
- 不应有让你选择“可达／不可达结论”的控件，也不因普通路线成功自动保证可达。
- 展开「查看依據與缺口」「資料來源與限制」，检查当次路线来源与设施资料不足说明。官方链接不代表已加载设施内容。
- 勾选或取消需求，不应新增 `amap.com/v3/direction/` 请求。

日期未知／过期、冲突、已知障碍及必要职员协助等边界放在自动化测试中。页面没有情境选择器，不为了手测编造真实依据；有适用依据时障碍和协助条件直接显示，不能把未预约说成已安排。

## 6. 核验演示修改不保存

回到登入页，选择「家屬端」→「演示登入」，分别尝试：

- 在行程页面新增一个容易辨认的行程。
- 在「設定安全範圍」新增、编辑、删除常用地点，修改并保存围栏半径。
- 在「設定中心」修改布局设置，或通过「管理長者資料」修改演示长者名称。

**预期：**修改在本页生效；跨页面、切换长者再回来仍保留；浏览器刷新后恢复预设，新增项消失，编辑或删除的预设项恢复。没有让用户配置存储方式的控件。

**写入检查：**Network选择All，清空记录后操作，筛选 `/api/memopath/`。演示业务操作不应出现POST／PUT／PATCH／DELETE；登录、登出等认证请求不算业务写入。地点搜索的高德请求也不算数据库写入。真实认证的demo账号也遵循同一页内保存规则。

## 7. 核验普通状态仍保存

登出演示身份，使用专门的**普通家属测试账号**登录，不能用demo账号。普通长者账号的管理权限受限制，不用它测试家属写入。

修改「鎖定長者頁面佈局」，等待服务器保存成功，再刷新、重新进入设置。

**预期：**修改仍保留，Network有成功的设置PUT请求。可再新增公共目的地行程，确认保存成功、刷新后仍存在。地点搜索失败时，应保留草稿并报告失败，不能显示假保存成功。

普通业务测试使用可清理的测试资料；自动化及数据库核验只用独立`_test`库，不操作真实照护资料。下面的受控浏览器fixture会刻意封锁高德，适合保存隔离与失败检查，不能用它宣称真实路线或新增行程的地点搜索成功。

## 8. 核验失败处理与手机页面

在已加载的导航页，把Network临时设为Offline，再切换一种出行方式，等待查询失败：

- 旧路线、摘要、指引和结论应清除。
- 起终点及方式保留，提供重试或修改地点。
- 恢复网络后点重试，应重新查询。
- 地图失败与路线失败分别提示，不返回假路线；已有路线文字不因单独地图错误而冒充查询失败。

只做一次有界故障核验，完成后把Network恢复为在线。实际迟到回应不易稳定制造，完整快切／身份／离页隔离由自动化测试补充。

最后用手机或开发者工具设为 **390×844**：检查没有横向溢出、三方式按钮易点（至少44px）、时间与距离易读；新结果的详细步骤和来源默认折叠，可按需展开。页面没有来源选择／模拟／回放／坐标输入／选结论控件，也没有独立控制台。用Tab检查模式按钮可获得焦点、Enter或Space可操作。
